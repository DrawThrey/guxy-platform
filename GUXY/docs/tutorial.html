第一章 了解 GUXY 是什么

01 欢迎来到 GUXY

GUXY 是一个围绕「卡片交互架构」设计的 游戏交互设计协同平台。它把策划案、交互设计、开发规划和 UI 设计统一到同一套结构之上，让不同角色可以围绕同一「源结构」协同工作。

GUXY 的核心价值
为什么要用它？
  • 统一语言： 使用卡片交互架构，将页面、模块、状态、交互关系统一抽象，避免策划、交互、UI、开发之间的口头「翻译损失」。
  • 结构驱动： 先有结构后有界面，一次梳理结构即可驱动 AI 生成开发规划、高保真 UI、交互文档等多种产出。
  • AI 协同： 通过 AI 自动解析策划案、补全交互细节，并在后续每一步持续提供智能建议，而不是一次性生成。
适用人群
你在这里能做什么？
  • 系统策划： 将策划案快速转化为清晰的交互架构，减少与设计 / 开发的反复解释与确认。
  • 交互设计师： 基于自动生成的卡片结构，继续补充交互细节、异常流程与状态，输出更可靠的交互方案。
  • UI 设计师： 直接在 GUXY 提供的结构上生成 / 调整高保真 UI，然后导出到 Figma / 设计系统。
第二章 5 分钟完成基础配置

02 快速开始：安装与首次配置

本章节帮助你从「没有环境」到「可以导入第一份策划案」——包括访问方式、首次登录配置以及 AI API 密钥的正确填写方式。

访问方式
在线 / 本地
  • 在线版本： 通过团队提供的 GUXY 访问链接，在浏览器中直接使用，无需本地安装。推荐大多数设计师与策划人员使用。
  • 本地版本： 用于需要本地部署或对数据有更高保密要求的团队。通常通过内部文档获取安装包与启动脚本（例如 Launch.bat）。

如你正在阅读本教程，大概率已经在正确的环境中。只需确认你能正常启动 GUXY 主界面即可继续。

首次登录与工作区
建议：1 人 1 工作区
  • 创建个人工作区： 第一次使用时，建议以个人账号或工号创建独立工作区，用于存放你负责的系统 / 项目。
  • 设置语言与主题： 在右上角设置中选择界面语言（推荐「简体中文」）和主题（深色 / 浅色）。你也可以通过本页面右上角开关先体验主题切换效果。
  • 本地存储位置： 若为本地版本，可在设置中查看当前项目存储路径，便于备份与同步。
配置 AI API 密钥
必做 · 否则无法调用 AI

为了让 GUXY 能够自动解析策划案与生成交互建议，你需要准备至少一个可用的 AI 模型提供方（例如 OpenAI / 国内大模型平台）的 API Key。

  1. 打开 GUXY 右上角设置，进入 AI 配置 页面。
  2. 在「模型提供方」下拉中选择你要使用的平台，例如 OpenAI 或团队内部代理服务。
  3. 将在平台后台获取到的 API Key 粘贴到对应输入框中，注意不要额外包含空格或换行。
  4. 点击「测试连接」，确认返回状态为「可用」，再保存配置。

如果你不确定自己是否有权限申请 API Key，可以先与技术负责人确认是否已有团队统一配置。

示意 · API 密钥配置界面
此处为「AI 配置」页面示意图，可在实际文档中替换为真实截图。
  • 左侧为「全局设置 > AI 配置」导航。
  • 中间为模型提供方下拉、模型名称、API Key 输入框。
  • 右上角有「测试连接」按钮，测试通过后会显示「连接成功」提示。
示例：通过环境变量配置 API Key（仅开发 / 本地部署时使用）
# Windows PowerShell
$env:OPENAI_API_KEY = "sk-xxxxx"

# macOS / Linux
export OPENAI_API_KEY="sk-xxxxx"
第三章 标准 7 步工作流程

03 从策划案到高保真 UI：7 步流程

以下 7 个步骤构成了 GUXY 推荐的完整工作流。每一步都包含 目标说明、操作步骤与注意事项，你可以按顺序执行，也可以根据团队分工拆分给不同角色。

  1. AI 分析策划案
    目标：提取页面 / 功能模块与关键流程 输入：一份清晰的系统策划案

    在首页点击「新建项目」，选择「从策划案导入」。上传或粘贴系统策划案文本，勾选需要重点解析的章节，例如「基础规则」「主流程」「界面说明」，随后点击「让 AI 分析」。

    • 建议先自行整理策划案结构（标题层级、章节划分），AI 更容易识别。
    • 对于已有旧项目，可仅粘贴本次改版相关部分，减少噪音。
  2. 生成卡片交互架构
    目标：得到一份「全局交互地图」 输出：卡片交互架构初稿

    在分析结果页中，点击「生成卡片交互架构」。GUXY 会根据策划案结构，自动创建页面节点、状态卡片与主要交互连线。

    • 重点检查：是否遗漏关键页面？是否有异常流程未生成？
    • 如果某部分结构明显不合理，可以选中相关卡片块，点击「重新让 AI 建议结构」。
  3. 手动调整卡片架构
    目标：把「AI 初稿」打磨成可落地结构 角色：交互设计 / 系统策划

    使用画布工具调整卡片布局、合并 / 拆分页面、补充状态与异常路径。你可以随时框选某一组卡片，右键调用 AI 帮你「补全异常情况」或「优化命名规范」。

    • 建议使用统一命名方式，例如「系统 - 页面 - 功能块」。
    • 对于交互复杂的状态（例如战斗、结算），可以单独抽出「子架构」卡片群。
  4. 导出 AI 可读架构
    目标：把结构转化为机器和人都能读懂的描述 输出：结构 JSON / Markdown 文档

    在右上角点击「导出」，选择「AI 可读结构」。GUXY 会生成一份包含 ID、名称、类型、交互关系的结构文档，可用于后续 AI 自动生成代码或联动外部工具。

    • 建议与开发同事确认字段命名是否符合项目现有规范。
    • 如需传给外部 AI 工具，可勾选「移除敏感字段」选项。
  5. 生成开发规划
    目标：自动拆分开发任务与优先级 输出：任务列表 / 里程碑

    在卡片架构视图中切换到「开发视图」，选择本次版本范围的卡片，点击「生成开发规划」。GUXY 会根据模块复杂度与前后置依赖，建议开发顺序与粒度。

    • 可以为不同团队（客户端 / 后端 / UI 实现）分别生成视图。
    • 支持导出为表格、Jira / 飞书多维表格所需格式。
  6. 开发与自检
    目标：确保实现与交互架构一致 角色：开发 / 测试 / 交互

    开发阶段可以以「卡片」为单位进行自检：每完成一张卡片，对照其输入 / 输出条件、状态变化与异常路径，完成「自检清单」勾选。

    • GUXY 可自动根据卡片结构生成「自检脚本」，包含关键操作路径。
    • 自检通过后，可以在卡片上标记状态（例如 Ready / In Review / Done）。
  7. 生成高保真 UI
    目标：在统一结构上完成界面视觉化 输出：高保真 UI / Figma 文件

    在卡片架构稳定后，切换至「UI 视图」，为关键页面指定 UI 模版与样式基线（例如项目内现有组件库），然后使用 AI 一键生成高保真原型。

    • UI 设计师可直接在 GUXY 中调整布局与样式，再导出到 Figma。
    • 确保「组件命名」与开发项目中的组件库保持一致，减少后续沟通成本。
第四章 主界面 · 工具栏 · 画布

04 界面操作指南

本章介绍 GUXY 主界面布局、工具栏功能，以及在画布中如何进行缩放、平移与选择。理解这些基础操作，将显著提升你的工作效率。

左侧：项目 / 结构导航 中间：卡片交互画布 右侧：属性 / AI 面板
项目列表 / 场景切换
工具栏：选择 · 连接 · 对齐 · 对齐网格
缩放控制 / 适配画布
中部为卡片交互画布，支持拖拽、缩放与多选操作。可通过鼠标滚轮缩放、按住空格键 + 拖拽进行平移。
画布操作
推荐：接近 Figma / Whiteboard 手感
  • 缩放： 使用鼠标滚轮缩放画布，按住 Ctrl / ⌘ 的同时滚动可更精细地调整缩放比例。
  • 平移： 按住空格键，光标会变为「抓手」，此时按住左键拖拽即可平移画布。
  • 选择： 单击选择单个卡片；按住 Shift 进行多选；在空白处拖动形成框选矩形，快速圈选一组卡片与连线。
  • 连线： 在卡片的输出锚点上按下并拖拽到目标卡片，即可创建交互连线；双击连线可编辑其条件或说明文字。

小技巧：当画布内容很多时，可以使用「缩略图 / 全局视图」快速定位当前所在区域。

项目管理
新建 · 保存 · 导出
  • 新建项目： 在左上角「项目」菜单中选择「新建」，可选择空白项目或从策划案导入。
  • 保存： GUXY 默认开启自动保存，你也可以随时点击顶部「保存」按钮，确保当前结构被写入磁盘。
  • 导出： 支持导出为交互结构 JSON、Markdown 文档、开发任务表格、Figma 接入文件等多种格式。
工具栏常用功能
熟练后极大提效
  • 对齐 / 整理： 选中多张卡片后，使用顶部「对齐到网格」「等间距分布」等工具，快速排布结构。
  • 分组： 将一组逻辑上相关的卡片分为一个「簇」，可折叠 / 展开，适合处理大型系统。
  • AI 建议： 在选中某一区域后点击 AI 按钮，可以请求「补全边界情况」「检查信息缺失」「生成说明文档」等。
第五章 模型选择 · Key 管理 · 常见问题

05 AI 配置详解

本章将更全面地介绍 GUXY 支持的 AI 模型类型、API Key 获取方法，以及在实际使用中常见的配置问题与排查思路。

支持的 AI 模型
按地区 / 合规性选择
  • 通用大模型： 例如 OpenAI、Anthropic、Azure OpenAI 等。适合文本解析、结构生成与对话式协作。
  • 国内大模型： 例如通义、文心、月之暗面等。适合对外网访问有限制或需本地化部署的团队。
  • 团队自建模型： 若团队已有自建模型服务，可通过 HTTP API 接口接入，只需在 GUXY 中配置对应的 Base URL 与认证方式。

不同模型在解析策划案与生成 UI 提示词时效果略有差异，建议先在小项目上试验，再确定团队推荐配置。

API Key 获取方法（示例）
以 OpenAI 为例
  1. 访问模型提供方官网，使用公司邮箱注册账号。
  2. 进入「API」或「开发者控制台」页面，创建新的 API Key。
  3. 将 Key 复制到 GUXY 的「AI 配置」页面中，并立即对原始 Key 进行妥善保存。
  4. 如需多人共用，优先使用团队 Key 或代理服务，不建议开发人员共享个人 Key。

安全提示： 不要在截图、视频录屏或公共文档中暴露完整 API Key。 如不慎泄露，请立刻在模型提供方后台作废该 Key 并重新生成。

常见配置问题与排查
当「测试连接」失败时
  • 网络问题： 检查本机 / 内网是否能访问模型提供方的域名，必要时请团队配置 HTTP / SOCKS 代理。
  • Key 无权限： 确认当前 Key 是否已开通目标模型的调用权限，或是否已超出账户额度限制。
  • Base URL 填写错误： 若使用代理或自建服务，确保 Base URL 不包含多余路径，例如不要重复填写 /v1。
  • 模型名称不匹配： 根据服务商文档填写准确的模型名称，如 gpt-4.1、 gpt-4o 等。
第六章 排查常见错误与使用疑惑

06 常见问题 FAQ

本章整理了部分高频问题，按「启动问题 / API 连接问题 / 数据存储问题」分类。如果这里仍未覆盖你的情况，建议将截图与日志反馈给技术支持。

  • 启动时窗口一闪而过 / 无法打开界面怎么办？ 启动问题
    • 确认已安装团队要求的运行环境（如 Node.js / .NET / 特定运行库）。
    • 尝试在命令行中手动运行启动脚本（例如 Launch.bat），查看是否有报错输出。
    • 如为本地版本，确认当前路径中不包含中文或特殊符号，必要时将整个项目移动到更简单的目录。
  • 「测试连接」提示 API 无法访问 / 超时？ API 连接问题
    • 先在浏览器中访问模型提供方的 /status 或示例接口，确认网络连通性。
    • 检查当前使用的代理工具是否对 GUXY 生效（有些仅作用于浏览器）。
    • 如果是公司内网环境，需由运维统一开通访问白名单或配置内部代理服务。
  • 项目内容会存到哪里？是否支持多人协作？ 数据存储问题
    • 在线版本通常存储在团队的云端项目空间，可通过账号登录在不同设备访问。
    • 本地版本项目一般保存在你本机的特定目录，可以通过 Git / 云盘进行手动同步。
    • 多人协作建议采用「一人一个分支 / 副本」，通过结构导入导出进行合并，避免同时编辑同一主项目造成冲突。

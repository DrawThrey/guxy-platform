# 蜂群模型使用示例

> 本文档提供蜂群模型在实际场景中的应用示例。

## 场景一：添加新功能模块

### 用户需求
> "给 GUXY 添加一个用户偏好设置面板，支持主题切换、语言选择和通知设置"

### 架构师模式执行

**1. 复杂度分析**
- 涉及文件数：5+
- 模块：UI组件、状态管理、CSS样式、本地存储
- 判定：**非琐碎** → 进入拆解流程

**2. 任务拆解**

```
整体目标: 添加用户偏好设置面板
├── 子任务 #1: 创建偏好设置数据模型和状态管理
├── 子任务 #2: 实现设置面板UI组件
├── 子任务 #3: 添加主题切换逻辑
├── 子任务 #4: 实现语言选择功能
└── 子任务 #5: 集成通知设置和持久化存储
```

**3. 生成任务卡片**

---

#### 任务卡片 #1

```markdown
## 任务卡片 #1

### 上下文边界
- 文件范围:
  - GUXY/modules/core/state.js (读取+修改)
  - GUXY/modules/core/constants.js (读取)
- 依赖项: 无

### 任务目标
创建偏好设置的状态管理模块

### 输入
- 现有的 GUXY.State 结构
- 需要支持的偏好项列表：theme, language, notifications

### 预期输出
1. state.js 中添加 preferences 对象
2. 添加 updatePreference 方法
3. 默认值初始化

### 约束
- 不读取: UI组件文件
- 不修改: 画布相关代码
```

---

#### 任务卡片 #2

```markdown
## 任务卡片 #2

### 上下文边界
- 文件范围:
  - GUXY/modules/ui/SettingsPanel.js (新建)
  - GUXY/styles/components.css (修改)
- 依赖项:
  - GUXY.State.preferences 结构
  - 模态框组件 API

### 任务目标
创建设置面板UI组件

### 输入
- 面板布局设计：标题栏 + 设置项列表 + 操作按钮
- 需要的设置项：主题、语言、通知

### 预期输出
1. SettingsPanel.js 组件文件
2. CSS样式：.settings-panel, .settings-item
3. show/hide 方法

### 约束
- 不读取: 状态管理实现细节
- 不修改: state.js
```

## 最佳实践

### 1. 卡片粒度控制

| 太粗 | 合适 | 太细 |
|------|------|------|
| "实现整个用户系统" | "实现登录表单验证" | "添加一个input标签" |

### 2. 上下文边界设定

```markdown
# 好的边界
- 文件范围: 明确的 3-5 个文件
- 依赖项: 具体的接口/数据结构

# 坏的边界
- 文件范围: "相关文件" (模糊)
- 依赖项: "参考整个项目" (过宽)
```

### 3. 预期输出编写

```markdown
# 好的预期输出
1. 添加 validateEmail 函数
2. 函数返回 { valid: boolean, error?: string }
3. 添加 3 个测试用例

# 坏的预期输出
- "完善验证功能" (不具体)
```

## 常见问题

### Q: 什么时候应该拆解任务？

A: 当任务满足以下任一条件时：
- 涉及 3+ 个文件
- 需要修改多个模块
- 预估代码量 > 100 行
- 有明确的阶段性产出

### Q: 开发者遇到卡片外的问题怎么办？

A:
1. 停止执行
2. 输出阻塞报告
3. 返回架构师模式重新规划

### Q: 任务卡片可以中途修改吗？

A: 可以，但需要：
1. 开发者报告阻塞原因
2. 架构师评估后更新卡片
3. 通知相关卡片（如有依赖）
